# E-commerce SQL Analytics

Аналитический проект: исследование продаж интернет-магазина с помощью SQL.

## Стек

- **СУБД:** SQLite (для запуска локально) / PostgreSQL (опционально)
- **Инструмент:** DB Browser for SQLite
- **Датасет:** сгенерированные данные e-commerce (7 таблиц, ~8000 записей)

## Структура данных

| Таблица | Записей | Описание |
|---------|---------|----------|
| `categories` | 10 | Категории товаров |
| `products` | 100 | Товары: название, категория, цена, себестоимость |
| `customers` | 500 | Клиенты: имя, email, город, дата регистрации |
| `sellers` | 20 | Продавцы: имя, рейтинг |
| `orders` | 2000 | Заказы: дата, статус, связи с клиентом и продавцом |
| `order_items` | ~4000 | Позиции заказов: товар, количество, сумма |
| `reviews` | ~800 | Отзывы: рейтинг, комментарий, дата |

## Быстрый старт

```bash
# 1. Установите Python 3.8+ (если ещё не установлен)
# 2. Запустите загрузку данных
python load_sqlite.py
# 3. Откройте файл ecommerce.db в DB Browser for SQLite
# 4. Выполняйте запросы из папки sql/
```

## SQL-запросы

| Файл | Задача | Конструкции SQL |
|------|--------|-----------------|
| `02_revenue_by_month.sql` | Выручка по месяцам + накопительный итог | `JOIN`, `GROUP BY`, `strftime()`, `SUM() OVER()` |
| `03_top_products.sql` | Топ-10 товаров по выручке | `JOIN` (3 таблицы), `ORDER BY`, `LIMIT` |
| `04_avg_check_by_category.sql` | Средний чек по категориям | `JOIN` (3 таблицы), `AVG`, `COUNT DISTINCT` |
| `05_rfm_segmentation.sql` | RFM-сегментация клиентов | `CTE`, `NTILE() OVER()`, `CASE` |
| `06_conversion_by_status.sql` | Конверсия по статусам заказов | `SUM() OVER()`, `GROUP BY` |
| `07_mom_growth.sql` | Прирост выручки месяц к месяцу | `CTE`, `LAG() OVER()`, `NULLIF` |
| `08_seller_margin.sql` | Маржинальность по продавцам | `JOIN` (3 таблицы), расчёт маржи |
| `09_ab_period_comparison.sql` | Сравнение двух полугодий | `CTE`, `CASE`, `LAG() OVER()` |

## Ключевые выводы

- **RFM-сегментация** выделила 5 групп клиентов: от лояльных до потерянных — основа для email-рассылок и программ лояльности.
- **Топ-10 товаров** дают ~20% выручки — принцип Парето в действии.
- **Маржинальность продавцов** варьируется в широком диапазоне: рейтинг продавца не всегда коррелирует с маржой.
- **Сезонность:** рост выручки в Q4 — типичная картина для e-commerce (праздничный сезон).

## Заметки

- Все даты хранятся в формате `YYYY-MM-DD` (ISO 8601) — SQLite нативно работает с этим форматом.
- `strftime()` — функция SQLite для извлечения компонентов даты (год, месяц, день).
- Фильтр `status NOT IN ('cancelled', 'returned')` исключает отменённые и возвращённые заказы из расчёта выручки.
